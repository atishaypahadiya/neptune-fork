## A6a: transcription

**Double entry.** `fork.data.transcription.diff_passes` compares the two passes field by field.
- Both have 279 rows, and the rows match.
- 14 data cells disagree, across 9 fields.
- Each has exactly one entry in `data/historical/leverrier_1846_resolution_log.csv`, giving the
  two readings, the resolved value, the page of the third scan that decides it, and the reason.
- `reconcile` raises if a disagreement has no entry or an entry matches none. It builds the
  committed table, and every resolved value is in it.
- The free-text `notes` column is not data and is not compared.

**Spot check.** 28 of 279 rows (10.04 %) were checked twice against the Gallica scan, on 336
cells; both checks used the table with SHA-256 897f3cde1564…, the current one.

**What this does not cover.**

  disagreement resolved against the page image. 28 rows were then checked by hand against the

  transcriptions made the same way produces no disagreement. The 10 % human check is the only
  guard against that, and it found none.
- The other 251 rows have had no human check. The per-row arithmetic check (`test_historical.py`)
  covers every row.
- The print has its own errors: 7 misprints are logged (4 corrected, 3 logged only), none
  argued from an ephemeris.
  - One was found after the spot check, outside its sample: 1771 Dec 18, declination degrees
    12 → 16, found by the O − JPL calibration.
  - All three editions and both passes read 12, so it is an error in the print, not in the
    transcription.

## A6d: leakage

**Static: `tests/test_a6d.py`** (new; pure AST, nothing imported or run).

1. **Modules.** It collects every `fork` module reachable by import from the M6a–M6d modules:
   transcription, observations, calibration and `export/m6c` (which holds M6d's Peirce
   number). That is 32 modules and 338 functions.
2. **Call graph.** It builds one from the M6a and M6b functions and the M6c fit's `dataset`,
   `job_space`, `do_job` and `run_all`.
   - Calls are resolved by bare name to every function, method or class of that name, so the
     graph over-approximates the real one.
   - It reaches 197 functions in 20 modules, including the Horizons reader and the sampler.
3. **What it finds on the fit path:**
   - no string containing "neptune" (docstrings aside);
   - no use of the `NEPTUNE` body or `true_neptune_geocentric_longitude`;
   - no loop over `bodies.BODIES`, the only table that maps a name to Neptune;
   - no `JPL_*` comparison constant;
   - nowhere in the 32 modules is a precovery file named.

   The static check found no reference to Neptune on the fit path.
4. **It can see a read.** Eight functions in these modules do reference Neptune, all off the
   path:
   - the real-Neptune comparison in `hidden_mass`;
   - the cache prefetch in `horizons`;
   - the M5a and M5b synthetic exports.

   From one of them the same walk reaches a reader (`test_the_graph_carries_a_neptune_read_to_its_caller`).

**Runtime:**
`test_m6c.py::test_dataset_is_table77_with_the_frozen_error_model_and_never_reads_neptune`
guards every Horizons state read while the fit's data, context and Uranus box are built. It fails
on any request for Neptune.

**Limits.**
- Blind spots of the static check: dynamic dispatch (`getattr`, `eval`, `importlib`) and files
  opened through path strings built at run time. The runtime test covers the other side: it
  guards the Horizons reads themselves while the fit's data are built.
- The M6b calibration reads Uranus's JPL positions (O − JPL). The spec allows this: it is
  Uranus, not Neptune.
- M6d compares the posterior with Neptune's longitude on Galle's night, the constant 325.873°
  (`JPL_GALLE_LON_DEG`), as M6d defines. It is applied to the samples after sampling, never in
  the likelihood or the priors. The static check asserts that no fit-path function names it.

## A6d rule 5: the test fixtures (2026-11-09)

The default CI job now reads JPL Horizons states from a committed fixture,
`tests/fixtures/horizons/` (see its README). That fixture includes two Neptune epochs that
tests compare with. A6d gains a fifth rule so the fit can never read it:
- **Static** (`tests/test_a6d.py`): no module reachable from the fit's entry modules has a
  string constant (docstrings aside) containing "fixture", at module level or in any function.
  - `test_the_fixture_check_finds_a_planted_reference` shows the scan catches four planted
    forms: a `Path` join, an `np.load` string, an `os.path.join`, and a capitalised name in a
    method. It also shows a docstring mention is not flagged.
- **Runtime** (`tests/test_m6c.py::test_fit_path_opens_nothing_under_tests_fixtures`): an audit
  hook records every file opened while `m6c.dataset()` builds the fit's data, context and
  Uranus box.
  - None is under `tests/fixtures/`.
  - The Horizons reads come from `FORK_CACHE_DIR`, which `tests/conftest.py` points at a
    temporary copy of the fixture. Outside pytest the variable is unset, and the cache is
    `data/cache/`.
- **Blind spot,** as for rules 1–4: a path assembled at run time from other strings.
