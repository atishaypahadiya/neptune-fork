# M1: Frames and data access

## Built
- `fork/model/bodies.py`: k = 0.01720209895, G = k². Sun/planet system mass ratios from the spec
  (Jupiter 1047.348644, Saturn 3497.9018, Uranus 22902.98, Neptune 19412.26). Inner planets
  (IAU 2009 ratios) folded into the central mass: M_central = 1 + 5.977e-6 M☉. `Body` records carry
  the Horizons id (barycenters 5–8; Earth = geocenter 399, used only as observing site).
- `fork/data/horizons.py`: Sun-centered (`500@10`), `refplane='ecliptic'`, geometric states in
  AU, AU/day at TDB JDs, fetched in chunks of 50. One merged cache per body
  (`data/cache/horizons_<body>.npz`); only epochs not already cached get fetched, and writes are
  atomic. `--fetch` caches the A1 epoch (1781-03-13 TDB) for all 5 bodies, plus a yearly 1690–1846
  grid for Uranus, Neptune and Earth (158 epochs each). Ran it; a second run made no network calls.
- `fork/data/frames.py`:
  - `ecl_j2000` is defined as **Horizons' ecliptic = astropy `HeliocentricEclipticIAU76`**
    (ICRF rotated by ε₀ = 84381.448″, no frame bias). `ecl_of_date` is astropy
    `HeliocentricMeanEcliptic(equinox=t)` (IAU 2006).
  - `precession_matrix_ecl_j2000_to_ecl_of_date(t)` is built by sending basis vectors through
    astropy at a common obstime, so it is a pure rotation that downstream numba code can apply.
    Lon/lat converters in both directions are built on top of it.
  - `elements_to_state` / `state_to_elements` / `solve_kepler_elliptic`: `numba.njit`, elliptic
    only. For degenerate orbits: planar → Ω = 0; circular → ω = 0. ϖ and λ are preserved either way.

## Surprises / decisions
- **1e-12 per element cannot be met near e = 0, so the test domain is split.** Ω, ω, M are only
  defined to about ε/sin i and ε/e: rounding (r, v) to doubles already shifts ω by ~2e-13 at
  e = 1e-3. So per-element 1e-12 is asserted for e, sin i ≥ 0.01. Below that, the test checks the
  well-conditioned combinations (λ, eccentricity vector, node vector) to 1e-12, plus a
  state→elements→state round trip. This matters for M5: the perturber prior includes e → 0, so
  sample in (e cos ϖ, e sin ϖ) or accept that ϖ is ill-defined there.
- **The ±1″ tolerance on "5029″ per century" only holds near J2000.** Over 1746–1846 the change
  is 5024.3″. A constant 50.29″/yr would be off by **11.3″ at 1690**, 5.8″ at 1781 and 2.9″ at
  1846, which is several σ of the synthetic noise. We always use the full IAU 2006 model via
  astropy, never a linear rate.
- **Horizons ecliptic ≠ astropy HeliocentricMeanEcliptic(J2000)** (by 0.04″). That's negligible
  at our 3″ scale, but it is why `ecl_j2000` is defined as IAU76 and every conversion goes through
  astropy. The live test asserts both the match and the mismatch, so a future frame swap will fail
  loudly.
- **A first draft of the frame test could not fail.** `acos(dot)` can't resolve angles below
  ~3 mas, yet the threshold was 1 mas; it printed exactly 0. The test now uses
  `atan2(|a×b|, a·b)`.
- astropy/ERFA warns about pre-1900 dates (`epv00` Sun ephemeris, "dubious year" UTC). Both
  affect only the Sun-offset legs, which cancel at a common obstime, so they are suppressed
  inside `precession_matrix_…` and nowhere else.
- For M6: historical reductions (Bouvard, Le Verrier) used 19th-century precession constants
  (Bessel/Struve), not IAU 2006. Converting their "mean equinox of date" longitudes with IAU 2006
  is only right if their own precession error is modelled or shown to be negligible. Check this
  before trusting the historical fit.
